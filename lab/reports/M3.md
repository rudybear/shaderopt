# M3 report: precision demotion across platforms (desktop only so far)

Date: 2026-09-25. Device: RTX PRO 6000 Blackwell, driver 580.178.04. Budget: `lab/budgets.toml` defaults (FLIP mean 0.01 / p99 0.05, min speedup 10%). Per-shader detail: `lab/reports/<shader>.md`, `lab/analysis/<shader>.demote.json`.

## Method
1. Candidate sites from the M2 classification (float, no hard sink, not constant), minus the sites the f16 transform cannot demote (interface loads, image results, call results, pointer-parameter loads).
2. Single-site demotions (two cheapest predicted sites per shader) and greedy cumulative sets ordered by predicted FLIP p99: `zero` (sites whose f16 rounding changes no output code), `q4`/`q2`/`q1` (predicted p99 within 1/4, 1/2, 1x the budget), `all`.
3. Two forms: `RelaxedPrecision` decorations (`relaxed`) and explicit f16 arithmetic with converts grouped (`f16`, `shader-ir demote --group-converts`).
4. Prediction: the transformed module itself evaluated in the CPU model (the per-site model underestimates because the transform also converts operands and constants). Measurement: interleaved A/B, 2 rounds x 20 samples x 8 executions on train, 1 round on holdout, gates 1-4.

## Result: nothing accepted on desktop

| shader | best f16 set | measured speedup | worst FLIP p99 | relaxed |
|---|---|---|---|---|
| tonemap_aces | q2 (32 sites) | +1.3..1.9% | 0.032 (train/holdout), **0.97 on tonemap_extreme** | -1.0..+0.6% |
| color_grade | q2 (45 sites) | < 2% | within budget | no effect |
| gaussian_blur_h/v | q4 (19 sites) | < 2% | within budget | no effect |
| fxaa | zero (29 sites) | < 2% | 0 | no effect |
| others | | < 2% or slower | | no effect |

- **`RelaxedPrecision` is ignored by this desktop driver**, as the brief predicted. Every relaxed variant is within noise of the baseline.
- **Explicit f16 buys at most ~2%** on desktop; small sets are slower because the f16<->f32 converts cost more than the narrower math saves. This is a device-class result, not a verdict on the sites: on mobile GPUs with real fp16 ALU rate the same sets must be re-measured.
- **The NaN/Inf holdout scenario catches f16 overflow.** tonemap_extreme has inputs above 65504; every f16 set turns them into Inf and fails gate 3. Train-scenario ranges do not protect against holdout extremes. Before f16 can be accepted anywhere, either the range profile must include the extreme scenarios or a site must be excluded when its observed range exceeds f16.
- Predictions vs measurements: the module-level prediction tracks the measured FLIP (e.g. tonemap q2 predicted 0.0228, measured 0.026).

## Defects found and fixed during M3
- The f16 transform demotes a Function variable only if every load of it is listed; sets that included some loads failed to build. The driver now closes sets over variable loads (adds the missing loads when they are candidates, otherwise drops the site).
- Raw image dumps grew to 47 GB and triggered the host's memory guard; they are now deleted after metrics.

## Status vs the brief's M3 stop condition
"Stop after the first shader is accepted or conclusively rejected": on desktop, precision demotion is **conclusively rejected for every shader** at the current budget (no set reaches the 2% floor, let alone 10%). The transform, prediction and gates are ready for the mobile devices, where the decision is expected to differ.
